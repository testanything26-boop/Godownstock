ROLLIX — DEPLOY CHECKLIST (read this before every update)
==========================================================

THE GOLDEN RULE: a version is ONE SET of files. Never deploy part of a set.

Files in this package — upload ALL of them, together, in ONE GitHub commit:
  1. index.html
  2. app.py
  3. db.py
  4. schema.sql
(DEPLOY.txt itself does not need uploading.)

STEPS
  1. GitHub repo (Godownstock) -> Add file -> Upload files.
  2. Drag in ALL FOUR files above at once. Commit them together.
  3. Open Render and wait until the deploy finishes ("Live").
  4. Open the app and hard-refresh (phone: pull to refresh / reopen the tab;
     computer: Cmd+Shift+R).
  5. CHECK: the Home tab must show your real totals and NO red
     "Server app is outdated" banner.
       - Banner gone + totals correct  -> deploy is complete.
       - Banner still there            -> a file from the set is missing.
                                          Re-upload ALL FOUR files again.

STAFF PHONE SHOWS THE BANNER BUT ADMIN DOES NOT?
  The server is fine — that phone is holding a cached old page.
  On that phone: close the app/tab fully and reopen the site.
  If it persists: browser Settings -> Site settings ->
  godownstock.onrender.com -> Clear & reset, then reopen.
  (v2.9+ serves the page with no-store headers, so once every phone has
  loaded v2.9 once, stale pages stop happening.)

BEFORE using "Erase all data" (Backup tab, admin only):
  Download the Stock, Cutting and Wastage CSV reports first.
  Erasing cannot be undone.

V2.16 — RETURN CUTTING WEIGHT (changes in index.html, app.py, db.py
and schema.sql — upload all four files together as always)
  When the cutting section gives fabric back, open the roll and use
  the new "Return weight" button on that cutting entry in the roll's
  history. Enter the returned kg: the roll's balance goes back up and
  history gains a separate "Returned" line — the original cutting
  entry is never changed, so the full record is kept.
  Rules: returns are recorded against one cutting entry at a time,
  and the total returned against a cutting can never exceed what that
  cutting used (a 10 kg cut can take back at most 10 kg in total).
  If an exhausted roll (0 kg) gets weight back, it automatically
  returns to "In use". Anyone who can log cutting can log a return.
  The server adds the small history column it needs by itself on
  login — no SQL step for existing users (schema.sql carries it for
  fresh installs).

V2.15 — BULK EDIT (changes in index.html, app.py and db.py — upload
all four files together as always)
  New "Bulk edit" button on the Rolls page: change many rolls at once.
    Step 1: filter by inward date, company and colour, tick the rolls
            (or "Select all shown") — the edit applies ONLY to ticked
            rolls.
    Step 2: tick the fields to change — Company, Colour, Fabric, Dia,
            GSM and Godown — and type the new values. Unticked fields
            are left exactly as they are.
    Step 3: a check screen lists every roll with its old -> new values;
            nothing is saved until you press Save.
  Every changed roll also gets a "Bulk edit" entry in its history, so
  corrections can be traced later. The Rolls page itself also gains a
  Colour filter next to the Company filter. Inward dates and weights
  are NOT changed by bulk edit, so roll IDs never change.

V2.14 — LABELS PAGE COMPANY FILTER (only change from v2.13 is
index.html, but upload all four files together as always)
  The Print Labels page now has a Company (manufacturer) filter next
  to the layout picker. Pick a company and: the roll list below shows
  only that company's rolls (each row now also shows the company and
  the inward date), "Select all inwarded on <date>" selects only that
  date's rolls FROM that company, and "Select all" selects the shown
  rolls. "Clear" still clears every selection. The picked date is now
  remembered when the page redraws.

V2.13 — BULK ADD CLOSE BUTTON (only change from v2.12 is index.html,
but upload all four files together as always)
  The Bulk add page no longer closes when you tap the dark background
  behind it — a stray tap used to close the page and lose what was
  typed. It now closes ONLY from the round ✕ button at the top-right
  corner (or the Cancel button). Same for the "Check before saving"
  screen. All other pages keep their old behaviour.

V2.12 — DATE-BASED ROLL IDS, AND THE PLANNED FRESH START
  Roll IDs now carry the inward date: R<DDMMYY>-<number for that date>.
  Example: the first roll inwarded on 29 Oct 2026 is R291026-1, the
  second that day is R291026-2, and the first roll on 30 Oct 2026 is
  R301026-1 (the number restarts at 1 every date).
  The Rolls page also has Inward date and Company (manufacturer)
  filters, with a rolls count and kg summary for what is shown.
  Fresh start with this version, in this order:
    1. Deploy all four files (steps above); check the banner is gone.
    2. Backup tab: download the CSV reports if you want to keep records.
    3. Backup tab: Erase all data (type ERASE). This removes the old
       R-0001 style rolls for good; numbering then restarts on its own.
       Godowns are erased too — re-add them in Settings -> Company &
       godowns before adding rolls.
    4. Add rolls as usual; the new date IDs are automatic in Add roll
       and Bulk add (the Add form shows the exact next ID for the
       inward date you pick).
